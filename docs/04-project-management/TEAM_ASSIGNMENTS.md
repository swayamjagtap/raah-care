## 3. Responsibility Areas

The project work is divided into the following areas.

Responsibilities may include:
- Emergency management.
- Ambulance management.
- Assignment management.
- Hospital management.
- Resource management.
- Allocation and recommendation.
- API validation and integration.
- Database and service-layer consistency.

### 3.2 Patient Portal

Responsibilities may include:

- Patient information.
- Emergency status visibility.
- Cura Card integration.

### 3.3 Ambulance Portal

Responsibilities may include:
- Driver interface.
- Assignment visibility.
- Accept and reject actions.
- Emergency response workflow.
- Destination and handover coordination.

### 3.4 Hospital Portal

Responsibilities may include:
- Hospital profile management.
- Operational status.
- Resource availability.
- Incoming emergency coordination.
- Patient reception and handover.

### 3.5 Admin Portal

Responsibilities may include:
- Emergency monitoring.
- Dispatch coordination.
- Ambulance assignment.
- Hospital selection.
- Operational oversight.
- Emergency lifecycle monitoring.

### 3.6 Integration and Quality Assurance

Responsibilities may include:
- API contract validation.
- Cross-portal integration.
- End-to-end testing.
- Bug reporting.
- Regression testing.
- Documentation consistency.

## 5. Collaboration Rules

1. Every task should have one primary owner.
2. Shared work should have clearly defined boundaries.
3. API contracts must be communicated before dependent frontend work begins.
4. Changes to shared database models must be communicated to affected contributors.
5. Conflicting changes should be discussed before integration.
6. Important architectural decisions should be recorded in `DECISIONS.md`.
7. Completed work should be submitted through pull requests.

## 6. Responsibility Changes

When responsibilities change:
- Update the assignment register.
- Inform affected contributors.
- Update the task tracker.
- Identify dependencies that may be affected.
